# Project memory

The in-process state machine passes idempotency, least-load selection, fail-and-requeue, concurrency, conversation-checkpoint, stream dispatch, and pending-entry reclaim tests. The Compose profile was validated on 2026-09-24 with Redis 7, the React test chat, and a recreated runtime container: a completed request replayed from Redis with attempt count 1. A subsequent Compose run started two Redis Streams workers; one submitted entry completed once, replayed with attempt count 1, and the `agent-workers` group reported two consumers, zero pending entries, and zero lag. A deliberately delayed worker was terminated after receiving a stream entry; a replacement reclaimed it, finalized it once, and left zero pending entries. The standalone Python command remains in-memory when `REDIS_URL` is absent. `infra/terraform/gcp-multicluster` and `infra/terraform/aws-multicluster` each define separate primary and secondary managed clusters and passed `init`, `fmt`, and `validate` locally; neither has received a plan or apply. `docs/cloud-deployer-identity.md` requires a dedicated, short-lived deployer identity, private Terraform state, plan review, and separate AWS and GCP contexts. Kubernetes execution and cloud deployment remain unproven. The `kind` two-worker blueprint passed strict Kubeconform validation, but the local control-plane refused connections during bootstrap and was removed.
