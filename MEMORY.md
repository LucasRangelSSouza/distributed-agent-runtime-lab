# Project memory

The in-process state machine passes idempotency, least-load selection, fail-and-requeue, concurrency, conversation-checkpoint, stream dispatch, and pending-entry reclaim tests. The Compose profile was validated on 2026-09-24 with Redis 7, the React test chat, and a recreated runtime container: a completed request replayed from Redis with attempt count 1. A subsequent Compose run started two Redis Streams workers; one submitted entry completed once, replayed with attempt count 1, and the `agent-workers` group reported two consumers, zero pending entries, and zero lag. A deliberately delayed worker was terminated after receiving a stream entry; a replacement reclaimed it, finalized it once, and left zero pending entries. The standalone Python command remains in-memory when `REDIS_URL` is absent. A local Compose benchmark on 2026-09-24 submitted 48 unique requests at concurrency six: all completed, client-observed p50 was 56.88 ms, p95 was 147.95 ms, throughput was 61.89 requests/s, work split evenly between two workers, and Redis Streams reported zero pending and lag after completion. It is local deterministic-stub evidence, not a production capacity claim. The `kind` profile initially failed because Kubernetes 1.37 rejects this Docker Desktop host's cgroup v1. Pinning `kindest/node:v1.31.4` produced a ready three-node cluster. On 2026-09-24, it ran Redis, one gateway, and two Redis Streams worker pods across both worker nodes; an API request completed, a duplicate replayed once, worker scale-down and scale-up succeeded, a deleted worker was replaced, and a fresh request after replacement continued the Redis-backed conversation. `infra/terraform/gcp-multicluster` and `infra/terraform/aws-multicluster` each define separate primary and secondary managed clusters and passed `init`, `fmt`, and `validate` locally; neither has received a plan or apply. `docs/cloud-deployer-identity.md` requires a dedicated, short-lived deployer identity, private Terraform state, plan review, and separate AWS and GCP contexts. Future unused `v*` tags run the release workflow, which publishes a GHCR container with SBOM and provenance; `v0.1.0` predates the workflow and has no container artifact. Cloud deployment, autoscaling behavior, and multi-cluster failover remain unproven.
